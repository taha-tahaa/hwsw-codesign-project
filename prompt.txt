WHAT TAHA DECIDED, CAUGHT OR OVERRULED
================================================================================

 1. PLAN BEFORE IMPLEMENTING (prompt 2).  "We need to be careful and accurate."
    Why the benchmarks were profiled before anything was optimized, and why the
    analysis led the implementation instead of justifying it afterwards.

 2. THE BENCHMARK PAIR (prompt 3).  pyflate and raytrace, chosen from options
    with their trade-offs laid out.  Integer / control-flow versus
    floating-point is the spine of both reports, and is what lets one project
    motivate both accelerator paradigms taught in the course: dataflow for
    pyflate, systolic for raytrace.

 3. THE ENVIRONMENT RULE (prompt 5).  The most consequential correction in the
    project.  The AI had measured everything on the naranja HOST and had argued
    in the README that the host was preferable because CPython 3.12 supports
    -X perf.  That was a technical argument placed above a course requirement,
    and the AI was wrong to make it unilaterally.  The catch forced a full
    re-measurement inside the guest, changed every number in both reports, and
    corrected a prediction the earlier reports had got wrong - that hardware
    counters would be unavailable in a VM.  They work, given -cpu host,pmu=on.

 4. CRITICAL REVIEW AS A STANDING INSTRUCTION (prompts 4 and 6).  Produced the
    pass that found seven RTL defects - four array-level alignment bugs the
    existing testbench could not see, and an fp32_add normalize bug that was
    wrong on its second test vector.  Without it the project would have shipped
    hardware that was broken and passed its own tests.

 5. CREDENTIAL HYGIENE, UNDER A CONSTRAINT.  Course account details were to be
    kept out of a public repository, and the password could NOT be rotated -
    this submitter is not authorized to change it - so the fix had to be
    removal rather than rotation.  The audit stripped the account name from the
    repository, which meant deleting the host flame graphs (~800 embedded
    occurrences).  The password lives only in a runtime environment variable.

 6. EVIDENCE RATHER THAN ASSERTION (prompt 7).  The correctness gate existed
    and passed - but this file had also claimed testing on 14 extra bzip2
    streams that no script could reproduce.  A claim a grader cannot re-run is
    not evidence.  That question produced tools/verify_extra.py, which checks
    the decoder against LIBBZ2 - an oracle we did not write, so an error shared
    by baseline and optimized would still be caught.

 7. "DO NOT ASSUME THE CODE IS CORRECT" (prompt 8).  The most productive
    instruction in the project.  Auditing the RTL against its documentation,
    instead of re-reading the documentation, found that both bzip2 run-length
    stages were missing, the MTF alphabet was never loaded, six CSR registers
    existed only in a comment, sym_ready was tied high so the handshake was
    half implemented, and two of this file's own verification claims were
    false.  Building the missing stages is what made an end-to-end simulation
    possible; regress.sh went from eleven checks to fifteen.

 8. TWO CORRECTIONS TO THE AI's OWN TECHNICAL CLAIMS (prompt 10).  Both
    dictated, both right:
      * "Not one of these changes the algorithm" was an overstatement - the
        optimizations plainly do change algorithms and data structures.  It now
        reads that they preserve behaviour and output while replacing
        inefficient algorithms, data structures and interpreter operations.
      * "A systolic array has no control circuitry" was too strong.  It now
        reads that a conventional systolic array relies on regular,
        fixed-cadence data movement, and that a variable-length stream needs
        explicit valid/ready flow control to avoid misalignment - which is the
        actual reason pyflate gets a dataflow engine and raytrace does not.

WHAT THE AI DID WITHOUT BEING ASKED
================================================================================
  * Read Project.pdf, the grading policy, the CS-server and QEMU guides, and
    the lecture decks (accelerator patterns, bottleneck identification, the
    perf tutorials) before proposing anything.
  * Checked the brief's benchmark list against upstream pyperformance:
    "deepblue" does not exist there and is almost certainly "deltablue".
  * Profiled both baselines before writing a single optimization.
  * Built the correctness gate (tools/verify.py) and the per-optimization
    attribution tool (tools/ablate.py) rather than quoting single runs.
  * Left one real bug UNFIXED on purpose: CheckerboardSurface.baseColourAt()
    discards the result of v.scale(), so checkSize never takes effect.  Fixing
    it would change the rendered image, and the brief requires identical
    output.  It is flagged in the report instead.
  * Kept the optimized version's bulk read inside the timed region, so that
    replacing per-byte I/O is credited as an optimization rather than hidden
    outside the timer.
  * Bounded both hardware claims by Amdahl's law instead of quoting kernel
    ratios: intersection is 35.03% of optimized raytrace runtime, so a perfect
    intersection unit caps the frame speedup at 1.54x, not the ~12,000x the
    kernel ratio would suggest.


BEFORE THE PRESENTATION
================================================================================
The brief is explicit that the AI is an aid and not a substitute for
understanding, and that the assessment is of the submitters' understanding.
Code that is reviewed rather than typed is only as good as the review, so these
should be re-derived independently rather than taken on trust:

  * the snoopbits / find_next_symbol ratio of 2.3, and why it means the cost
    was call count rather than scan depth
  * the canonical limit/base/perm recurrence, and why prefix-free codes make
    the priority encoder exact
  * why variable-length codes forbid a systolic array, and why the fixed-shape
    intersection kernel invites one
  * the Amdahl bound on both accelerators
  * what the IPC row actually proves, and why cycles falling in step with the
    stopwatch is the sanity check

Every measurement is reproducible from the scripts inside the guest.  Running
them is the fastest way to confirm the reasoning holds.
